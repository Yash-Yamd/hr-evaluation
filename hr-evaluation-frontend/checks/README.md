# 削除中の表示と通信失敗後の解除を確認する

通常のアプリと同じ `src/App.jsx` を読み込む確認専用ページ。アプリ本体の処理は書き換えず、社員データ・通信・確認画面の返事だけをこのページ内で仮のものに置き換える。実際のAPIへは送信しない。追加インストールは不要。

## 操作

1. フロント側で `npm run dev -- --host 127.0.0.1` を実行する。
2. 表示された開発用URLの末尾に `/checks/delete-pending.html` を付けて開く。通常のポートなら `http://127.0.0.1:5173/checks/delete-pending.html`。
3. 「確認用部署 確認用 社員」を選ぶ。点数2・3・5・3・4、合計17点が表示される。
4. 確認専用のチェック欄をオンにし、「評価を削除」を押す。
5. 返事は保留される。「削除中です…」と、社員・5項目・保存・削除・相対評価の操作が無効であることを確認する。
6. 「通信失敗の返事を返す」を押す。失敗の案内、元のボタン表示、操作の有効化、点数と合計17点の保持を確認する。

## 2026年10月16日の確認結果

ブラウザの表示内容と各入力・ボタンの無効状態を読み取り、次の9項目がすべて一致した。

- 待機中の「削除中です…」表示。
- 待機中の3つの操作ボタンの無効化。
- 待機中の社員と5項目の無効化。
- 通信失敗後の「評価を削除」表示への復帰。
- 通信失敗後の3つの操作ボタンの有効化。
- 通信失敗後の社員と5項目の有効化。
- 点数2・3・5・3・4の保持。
- 合計17点の保持。
- 削除失敗の案内表示。

これは実際の画面部品に仮の通信失敗を返した確認であり、実API・MySQL・本物の確認ダイアログの試験ではない。それらは別の操作確認と区別する。確認を繰り返す場合はページを再読み込みする。

## 2026年10月17日追加：通常操作の時間測定

`operation-timing.html` は本体と同じApp.jsxを表示し、実際のAPI・MySQLへ通信する。仮の通信への置き換えは行わない。本体のコードを変更せず、操作から成功画面への反映に要した時間を測る確認専用ページであり、通常の製品画面には測定欄を表示しない。

1. MySQL・バックエンド・フロントエンドを通常どおり起動する。
2. Chromeで `http://127.0.0.1:5173/checks/operation-timing.html` を開く。
3. 保存済み評価のある社員を選ぶ。5項目が選択済みになり、操作可能になるまで測定する。
4. 点数を変更せず「評価を保存」を押す。「更新しました」等の成功表示と保存ボタンの復帰まで測定する。本物の保存処理が実行される。
5. 全12人が保存済みの場合に相対評価を実行する。結果画面に12行が表示されるまで測定する。
6. 戻るボタン→社員を未選択→同じ社員を選択、の順で繰り返す。次の操作は測定中の表示が終わってから行う。

開始は操作イベントをReactが処理する直前、終了は成功した画面の更新を検出した後の2回のrequestAnimationFrame。ブラウザの描画機会までを含む実用上の近似値であり、ディスプレイへ実際に映った時刻そのものではない。30秒以内に成功を検出できない場合は成功扱いにしない。未保存社員の読み込み、初回起動、削除、新規登録、他PC、多人数の同時操作はこの測定に含めない。

### 測定結果

Windows・Chrome、開発用Vite、起動済みSpring Boot・MySQL、同じPC、架空の社員12人、1操作ずつで各3回測定した。測定には確認用の表示・監視処理も含む。大野美咲の2・3・5・3・4（17点）を変更せず更新し、毎回12人分の相対評価結果を確認した。

| 対象 | 1回目 | 2回目 | 3回目 | 最大 |
| --- | ---: | ---: | ---: | ---: |
| 保存済み評価の読み込み | 0.088秒 | 0.119秒 | 0.168秒 | 0.168秒 |
| 同じ点数で更新保存 | 0.243秒 | 0.343秒 | 0.344秒 | 0.344秒 |
| 相対評価の12人分の表示 | 0.135秒 | 0.117秒 | 0.110秒 | 0.135秒 |

測定した9操作はすべて3秒以内だった。全操作・全環境での性能保証や数十人規模の達成確認とは扱わない。初回画面表示・新規保存・削除の所要時間は未測定。DBの停止や負荷、ブラウザの背景状態などで時間は変わる。
